Finding 11: Weak Origin Validation — Credential File Write PoC

1. Origin Validation Analysis

The extension validates postMessage origins using wildcard-match with these patterns:

Allowed patterns:
  "https://**.v2.*.beta.app.*.aws.dev"        — any deep subdomain under v2.*.beta.app.*.aws.dev
  "https://**.ui.*.aws.dev"                    — any deep subdomain under ui.*.aws.dev
  "https://**.v2.*-gamma.*.on.aws"             — gamma environment wildcard
  "https://**.datazone.*.on.aws"               — DataZone wildcard
  "https://**.sagemaker.*.on.aws"              — SageMaker production wildcard
  "https://**.sagemaker-gamma.*.on.aws"        — SageMaker gamma wildcard

The ** glob matches ANY characters including dots, so:
  "https://EVIL.sagemaker.us-east-1.on.aws"  → PASSES validation
  "https://x.y.z.ui.foo.aws.dev"            → PASSES validation

5. Impact Summary

  
Files written by updateMetadata() via Jupyter Contents API (PUT /api/contents/...):

  .aws/sso/idc_access_token.json
    → Overwrites IAM Identity Center access token
    → Attacker can inject their own token to hijack the session
    → All subsequent AWS API calls use the attacker's token

  .aws/amazon_q/q_dev_profile.json
    → Overwrites Amazon Q Developer profile ARN
    → Redirects Q Developer requests to attacker-controlled profile

  .aws/amazon_q/settings.json
    → Controls auth_mode (IAM vs SSO) and q_enabled flag
    → Can disable Q or force a different auth mode

  .aws/enabled_features/enabled_features.json
    → Controls feature flags for the environment
    → Can enable/disable features to alter behavior

After writing, the extension also triggers cache invalidation:
  POST /aws/sagemaker/api/cache
  POST /amazon_q_developer_jupyterlab_ext/clear_environment_cache

This forces the environment to reload credentials from the now-poisoned files.
